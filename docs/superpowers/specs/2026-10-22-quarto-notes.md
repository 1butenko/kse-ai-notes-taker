# Доопрацювання конспектів через Quarto: специфікація

Статус: початкова специфікація від 2026-10-22; у гілці `feature/quarto-notes` реалізовано P1.1–P3.3. Реальні перевірки контрольного курсу описано в [E2E](../../../web/e2e/notes/README.md); обмеження перегляду Word наведено в [README](../../../README.md).

Ухвалені архітектурні рішення, записані під час виконання: [рішення](2026-10-23-quarto-notes-decisions.md).

## Мета та обсяг

Викладач отримує структурований конспект, читає його в HTML, редагує тему вручну або за допомогою AI, перевіряє зміни та експортує актуальну версію. Студент читає теми окремо або як книгу курсу з навігацією й пошуком.

Увесь погоджений напрямами обсяг:

1. Єдина навчальна структура теми: інтуїція, означення, приклад із розв'язанням, підсумок; доведення й інші блоки — коли потрібні та забезпечені джерелами.
2. Узгоджені callouts для означень, теорем, прикладів і зауважень.
3. Математика, таблиці, рисунки, нумерація та перехресні посилання.
4. Джерела зі сторінками та бібліографія без вигаданих метаданих.
5. Адаптивний HTML, PDF теми й усього конспекту, Word-експорт.
6. Ручне редагування, історія, порівняння та відновлення версій.
7. Точкове AI-доопрацювання з переглядом змін перед застосуванням.
8. Книга курсу з навігацією, пошуком і переходами між темами.

## Вихідна база

Базова гілка плану — `notes-generation-engine`, перевірений commit `2829b7b`. Вона вже має `NotesDocument`, IDs тем і блоків, джерела, перевірку тем, Quarto/Typst PDF та preview із PDF у iframe. Це можливості, які треба розвинути й зберегти.

`origin/engine-reset` (`e7c2a2f`) мав іншу архітектуру: офлайн-модель і writer `.qmd` без завершеного рендерингу. Реалізацію зроблено поверх `notes-generation-engine` у `feature/quarto-notes`; автоматичного злиття з `engine-reset` не було.

## Архітектурні рішення

- Основне джерело змісту — структурований `NotesDocument`. `.qmd` та кінцеві файли є похідними. Прямого двостороннього редактора довільного `.qmd` у цій ітерації немає.
- Початковий результат генерації зберігається. Подальші зміни утворюють незмінні знімки ревізій; HTML/PDF/DOCX прив'язані до конкретної ревізії.
- Усі зміни ревізій і рендеринг проходять через worker. API читає стан та передає команди через наявний `WorkerClient`.
- Файлове сховище та один worker deployment зберігаються. Запис ревізії має міжпроцесне блокування на run і перевірку `base_revision`; конфлікт повертає HTTP 409. На macOS/Linux використати стандартний `fcntl.flock`; не будувати розподілену чергу в цьому обсязі.
- Ручне збереження та повторний рендер не викликають LLM. AI створює пропозицію, а не змінює документ автоматично.
- Редагована тема втрачає попередній статус `verified`, отримує `unresolved` та `verification_stale=true`. Повторна перевірка записує новий результат. Відновлення старого тексту також потребує актуальної перевірки.
- HTML та Word не повинні використовувати специфічні для Typst перетворення математичного тексту. Поточний `typst_safe` застосовується лише у відповідному виході.
- PDF залишається на Typst; додатковий LaTeX toolchain не вводиться. Для HTML використовувати MathJax; друковані та інтерактивні варіанти перевіряти окремо.
- Нових бібліотек для rich-text editor не потрібно: початкова реалізація — редактор блоків Markdown/LaTeX, поруч перегляд збереженої ревізії. Автоперегляд незбереженого тексту можна додати пізніше.
- Нові маршрути успадковують чинні правила доступу проєкту; існуючий URL не вважається механізмом авторизації. Публічний деплой і нова система облікових записів не входять у цей план.

## Глобальні вимоги

- Python >=3.12; FastAPI/Pydantic; наявний Next.js/React/TypeScript стек.
- Мови конспекту: українська (`uk`) та англійська (`en`); збережена мова документа використовується для повторного рендерингу.
- Старі `notes.json`, URL preview та завантаження PDF/QMD продовжують працювати.
- Не вигадувати факти, джерела, авторів, роки або номери сторінок для заповнення шаблону.
- Ручні правки не перезаписуються командою resume; повторна генерація створює новий run або явну пропозицію.
- Незмінені IDs тем/блоків та пов'язані джерела зберігаються між ревізіями.
- Користувач бачить номер ревізії тексту та ревізію показаного артефакту; старий PDF не позначається актуальним.
- Помилка рендерингу не видаляє збережений зміст або попередній успішний артефакт.
- Для текстових конспектів вимкнене виконання code cells; контрольовані конфігурація, локальні ресурси й серверні шаблони.
- HTML-перегляд не отримує довільного доступу до застосунку через згенерований HTML/JavaScript.
- Книга формується з однієї ревізії, а пошук не включає приватні підручники та проміжні AI-артефакти.

## Сценарій приймання

На контрольному курсі з двома темами викладач відкриває HTML, знаходить означення й формулу, переходить за посиланням на іншу тему та перевіряє джерело зі сторінкою. Виправляє один блок; друга тема не змінюється; у mock LLM немає запитів. Бачить нову ревізію, оновлений HTML і PDF. Переглядає історію, відновлює попередній текст як нову ревізію. Просить AI додати приклад, бачить diff, відхиляє або застосовує пропозицію. Завантажує PDF і DOCX; відкриває книгу курсу та знаходить термін пошуком.

Окремо перевіряються одночасне редагування у двох вкладках, відсутні джерела, недоступний Quarto, перезапуск worker, невалідна формула, українські символи та довгі таблиці. Незавершені та неперевірені теми явно позначені.
