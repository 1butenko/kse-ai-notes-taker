# Fix the deploy: Python 3.12 image, OIDC subject for the deploy role

- **Date:** 2026-11-19
- **PR:** #57
- **Branch:** fix/deploy-role-env-case → main

## What changed
- The API image is built from `python:3.12-slim` again. The Dependabot bump to 3.15 broke the production build.
- Dependabot no longer proposes minor or major updates of the `python` Docker image.
- `github-deploy-role.sh` reads the OIDC subject prefix from GitHub (`gh api .../actions/oidc/customization/sub`), falling back to `repo:<owner>/<repo>`, or to `SUB_PREFIX` if set.
- The role trust policy accepts `<prefix>:environment:production` and `<prefix>:environment:Production`.

## Why
The first CD deploy (#56) failed. `zstandard` has no Python 3.15 wheel and the slim image has no gcc. The repo uses GitHub's immutable OIDC subjects (`repo:owner@id/repo@id`) and the environment is named `Production`, so the old trust condition never matched.

## Where
- [api/Dockerfile](../../../api/Dockerfile): base image `python:3.12-slim`.
- [.github/dependabot.yml](../../../.github/dependabot.yml): `ignore` for `python` minor and major updates in the `docker` ecosystem.
- [scripts/aws/github-deploy-role.sh](../../../scripts/aws/github-deploy-role.sh): `SUB_PREFIX` lookup and two-subject trust condition.

## API and data
None. New optional env var for the script: `SUB_PREFIX`.

## How to try it / migrate
The role is already updated in AWS and `AWS_DEPLOY_ROLE_ARN` is set on the environment. After merge, CI → Deploy should ship `main` to EC2. To recreate the role, run `scripts/aws/github-deploy-role.sh` (needs `aws` and `gh`).
