# Make the note checker's line checks linear-time (CodeQL ReDoS)

- **Date:** 2026-11-23
- **PR:** #67
- **Branch:** fix/codeql-redos → main

## What changed
- The lecture-notes validator no longer uses backtracking regexes on a teacher's text, so no line check takes polynomial time.
- Inline code spans are paired by backtick-run length (as CommonMark does) in `strip_code_spans`, not by a backreference regex.
- Code fences, div fences and metadata lines are read with plain `str` methods.
- Image and autolink regexes leave the opening character out of the scanned class; inline HTML tags are found by `html_tags`, a `find()`-based scanner with the same result as the old `findall`.
- Small difference: `![a[b](x)` (alt text containing `[`) is no longer read as an image; its target is still checked as a link and refused, so the note is still rejected.
- The 5,000-character line cap (`MAX_LINE_CHARS`) stays as a second guard.

## Why
CodeQL still flagged eight `py/polynomial-redos` alerts after the line cap from #64, because it cannot see the cap. `parse_attributes` (alert #2) is judged a false positive and left as is.

## Where
- `api/app/note_taker/lecture_notes/validate.py`: `strip_code_spans`, `html_tags`, `TAG_NAME`, and the rewritten fence, metadata, div, image and autolink checks.
- `api/tests/test_lecture_notes.py`: crafted lines at the cap, and a comparison of the new scanners with the old regexes.
