# Docs bot: maintain all project docs on every PR

- **Date:** 2026-11-18
- **PR:** #51
- **Branch:** docs/maintain-docs-on-pr → main

## What changed
- On every same-repo, non-draft, non-Dependabot pull request, Claude updates every doc the code change affects, writes one change entry (`changes/<date>-pr<number>.md`) and commits to the PR branch. Docs merge with the code.
- Every Monday 06:00 UTC, and on manual runs, an audit mode checks all maintained docs against the branch, fills stub docs and opens a `docs/audit-<branch>` PR.
- The prompt now has a docs map (code path to doc), a fixed shape for area docs, read-only history docs, and fact-only fixes for `CLAUDE.md` files and the skill.
- A workflow step reverts any change outside the maintained docs before committing.
- Runs triggered by the bot's own docs commit are skipped (`docs.yml` and `claude-code-review.yml` check `github.actor != 'github-actions[bot]'`), so one push does not start extra Docs runs or a failing review.
- `dev-docs.yml` and `dev-docs.md` are renamed to `docs.yml` and `docs.md`; the old push-triggered `dev-docs/<branch>` PRs stop.

## Why
The docs commit pushed by the workflow does trigger pull_request workflows here: each push started another Docs run and a Claude review that fails on bot actors, leaving a red check. The old workflow ran after each push, only wrote `docs/dev/`, and opened a separate PR that mostly appended a change entry. The area docs on `main` were still stubs, and `README.md`, `docs/note-taker/` and the `CLAUDE.md` files were not maintained. Closes #41, part of #42.

## How to try it / migrate
After merge, run **Docs** manually on `main` (Actions, Docs, Run workflow) to fill the stub area docs in one audit PR. Close the old `dev-docs/*` PRs and branches. Secrets: `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN`.
