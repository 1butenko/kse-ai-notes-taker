# Quarto для доопрацювання конспектів

Дата дослідження: 2026-10-22. Перевірено офіційну документацію Quarto та код `notes-generation-engine` (`2829b7b`) і `origin/engine-reset` (`e7c2a2f`). Нижче можливості Quarto відділено від пропозицій для нашого застосунку. Реалізацію не змінено; рендеринг прикладу в цьому дослідженні не запускався.

## Що може означати завдання

Формулювання «зробити доопрацювання конспекту, треба ресьорчити Quarto» неоднозначне. Ймовірні два пов’язані напрями:

1. **Покращити вигляд і структуру результату:** формули, блоки означень і прикладів, зміст, джерела, зручне читання та якісний PDF.
2. **Дати можливість допрацювати вже створений текст:** змінити розділ, додати приклад або уточнити доведення й отримати оновлені версії документа.

Quarto забезпечує підготовку й складання документа. Збереження редагувань, історія версій та команда «поясни простіше» потребують окремої логіки нашого застосунку. Це інтерпретація завдання та архітектурна пропозиція, а не вже погоджені вимоги.

## Що таке Quarto

Quarto перетворює текстовий вихідний документ `.qmd` на матеріал для читання: HTML, PDF, Word тощо. `.qmd` містить Markdown і YAML з параметрами оформлення; також може містити виконуваний код. Для звичайного конспекту обчислення не потрібні. [Офіційний вступ](https://quarto.org/docs/get-started/hello/text-editor.html), [формати результату](https://quarto.org/docs/output-formats/all-formats).

Приклад процесу: `зміст конспекту → .qmd → Quarto → HTML для читання / PDF для друку`. Виправлення тексту може запускати лише повторне складання; звернення до LLM для цього не потрібне. Останнє — рекомендація для нашого процесу.

## Як саме покращити конспекти

| Доопрацювання | Можливість Quarto | Що потрібно додати в нашому застосунку |
|---|---|---|
| Зручна структура | Заголовки, зміст, нумерація розділів. [HTML Basics](https://quarto.org/docs/output-formats/html-basics.html) | Єдиний шаблон теми: пояснення → означення → приклад → підсумок; перевірка, що він відповідає матеріалу. |
| Чіткі акценти | Callouts `note`, `tip`, `important`, `warning`, `caution`. [Callout Blocks](https://quarto.org/docs/authoring/callouts.html) | Послідовне відображення типів навчальних блоків; частина вже реалізована. |
| Зрозуміла математика | Inline `$…$`, окремі формули `$$…$$`. [Markdown Basics](https://quarto.org/docs/authoring/markdown-basics.html) | Перевіряти матриці, індекси, довгі формули та потрібні макроси в HTML і Typst/PDF. |
| Навігація між поясненнями | Стабільні мітки та посилання на формули, рисунки, таблиці й розділи. [Cross References](https://quarto.org/docs/authoring/cross-references) | Узгодити IDs у структурованому документі та `.qmd`, зберігати їх після редагування. |
| Акуратні джерела | Бібліографія, ключі цитувань, сторінки та CSL. [Citations](https://quarto.org/docs/authoring/citations.html) | Зберігати відповідність твердження → перевірене джерело → сторінка. Quarto оформлює цитування; достовірність визначає наш процес перевірки. |
| HTML + PDF + Word | Різні виходи з одного джерела. [All Formats](https://quarto.org/docs/output-formats/all-formats) | Спочатку завершити HTML + наявний PDF; DOCX додати за потреби, з окремою перевіркою верстки. |
| Конспект усього курсу | Book об’єднує розділи; HTML-книга підтримує пошук і перехресні посилання. [Books](https://quarto.org/docs/books/) | Опис структури курсу, складання й доступ до результату; це наступний етап після однієї теми. |

Повнотекстовий пошук Quarto працює для зібраного website/book і використовує локально створений індекс за замовчуванням. Це не семантичний пошук по завантажених підручниках і не готовий пошук у нашому React-застосунку. [Website Search](https://quarto.org/docs/websites/website-search.html).

## Як може виглядати доопрацювання користувачем

Пропонований сценарій: користувач відкриває тему «Власні значення», виправляє приклад або просить AI додати пояснення; переглядає зміни; зберігає нову версію; отримує оновлений HTML і PDF.

Відповідальності для реалізації:

- Застосунок: редактор, вибір розділу, збереження, історія, порівняння версій, за потреби точкова генерація через LLM.
- Модель конспекту: IDs тем і блоків, джерела, статус перевірки, вміст та ревізія.
- Quarto: перетворення погодженого вмісту на оформлений результат.

Для поточної гілки доцільно залишити `NotesDocument` основним джерелом даних, генеруючи `.qmd` з нього. Інакше наступна генерація може перезаписати ручні зміни у файлі. Якщо обрати пряме редагування `.qmd`, треба явно спроєктувати його синхронізацію з моделлю; це альтернативне архітектурне рішення.

## Мінімальний технічний процес

1. Отримати або змінити один розділ структурованого конспекту.
2. Зберегти ревізію, IDs та зв’язки з джерелами.
3. Побудувати `.qmd` із перевірених шаблонів.
4. Запустити Quarto в окремому render-процесі, отримати HTML і PDF.
5. Показати результат або зрозумілу помилку, залишивши попередню успішну версію доступною.

Для розробки є `quarto preview notes.qmd`: він перебудовує перегляд після збереження файлу. Для готового артефакту є `quarto render`; це не API для редагування у нашому UI. [Authoring workflow](https://quarto.org/docs/get-started/hello/text-editor.html).

Орієнтовна конфігурація, яку треба перевірити на зафіксованій версії CLI:

```yaml
---
title: "Власні значення та власні вектори"
lang: uk
engine: markdown
execute:
  enabled: false
format:
  html:
    toc: true
    number-sections: true
    html-math-method: mathjax
  typst:
    toc: true
    number-sections: true
    papersize: a4
    mainfont: DejaVu Serif
---
```

```bash
quarto render notes.qmd --to html --no-execute
quarto render notes.qmd --to typst --no-execute
# За потреби Word:
quarto render notes.qmd --to docx --no-execute
```

`typst` тут означає PDF через Typst. Для стандартного `format: pdf` з LaTeX потрібен TeX-дистрибутив, наприклад TinyTeX; встановлювати його лише заради чинного Typst-процесу немає потреби. Для Typst шрифт має бути доступний у системі або через `font-paths`. [Typst Basics](https://quarto.org/docs/output-formats/typst.html), [PDF Basics](https://quarto.org/docs/output-formats/pdf-basics).

## Обмеження, які впливають на рішення

- **Однаковий текст не означає однакову верстку.** Згортання callout — можливість HTML; PDF потребує статичного представлення. Raw LaTeX ігнорується у HTML/Word, а деякі налаштування crossrefs не працюють для LaTeX/PDF. Потрібна окрема візуальна перевірка форматів. [Callouts](https://quarto.org/docs/authoring/callouts.html), [PDF Basics](https://quarto.org/docs/output-formats/pdf-basics), [Cross-Reference Options](https://quarto.org/docs/authoring/cross-reference-options.html).
- **Українська потребує перевірки на обраній версії.** Поточний код використовує `uk`. Документація описує `lang` та власний YAML перекладів, але у списку вбудованих перекладів позначає Ukrainian як `ua`. Перевірити службові підписи, кирилицю та переноси; за потреби задати `language:` явно. Приклад вище не є результатом такого тесту. [Document Language](https://quarto.org/docs/authoring/language.html).
- **Рендеринг може виконувати код.** Для текстових конспектів доцільні `engine: markdown` і `--no-execute`; це не повна ізоляція недовірених документів. Рекомендація для сервера: контрольований YAML, дозволений набір конструкцій/ресурсів, ізольований renderer і обмеження часу; не приймати довільні filters/scripts/includes від LLM чи користувача. [Execution Options](https://quarto.org/docs/computations/execution-options.html), [render CLI](https://quarto.org/docs/cli/render.html).
- **Посилання не гарантують правильності.** Бібліографічне оформлення не перевіряє, чи підтверджує сторінка конкретне твердження. Для Typst також треба врахувати окрему типову систему обробки цитувань. [Citations](https://quarto.org/docs/authoring/citations.html).

## Пропоноване формулювання задачі й MVP

> Додати доопрацювання окремої теми конспекту зі збереженням джерел та історії версій. Після ручного редагування або погодженого AI-оновлення будувати узгоджені HTML і PDF через Quarto, зберігши чинний експорт повного конспекту та PDF окремої теми.

Критерії приймання пропозиції:

1. Можна змінити один розділ і його посилання на джерела, зберігши IDs інших розділів та попередню ревізію.
2. Ручне редагування запускає повторний рендеринг без LLM-виклику.
3. HTML зручний на мобільному екрані, має зміст і коректну математику; PDF доступний для теми та повного конспекту.
4. Контрольний документ містить український текст, матрицю, індекси, довгу формулу, таблицю, callout і посилання на джерело зі сторінкою; HTML і PDF перевірені візуально.
5. Помилка складання показана користувачу, попередній успішний артефакт доступний; виконання довільного коду вимкнено.

Це рекомендований обсяг для подальшого узгодження. Дослідження не реалізує редактор, зберігання чи експорт.
